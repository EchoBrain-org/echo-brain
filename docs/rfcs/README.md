# Requests for comment

Use an RFC for a proposed cross-component, protocol, persistence, permission,
cryptographic, migration, or deployment change that requires coordinated
review before implementation.

An RFC is not an accepted decision. When its significant choices are accepted,
record the durable result in one or more ADRs and link the implementation and
qualification status separately.

## Required content

- problem, goals, non-goals, and affected components;
- current and proposed flows;
- trust boundaries and threat analysis;
- protocol, schema, state, and compatibility changes;
- alternatives and tradeoffs;
- rollout, migration, observability, and rollback;
- affected invariants and failure patterns;
- qualification plan; and
- unresolved questions and disposition.

Use the [RFC template](../_templates/rfc.md).
